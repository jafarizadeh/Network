\section{Introduction to Network Topology for FHRP Implementation}

\begin{figure}[h]
\centering
\includegraphics[width=0.9\textwidth]{img/FHRP.png}
\caption{\textit{}}
\end{figure}


This network topology is designed to demonstrate the implementation and functionality of First Hop Redundancy Protocols (FHRP), including \textbf{HSRP (Hot Standby Router Protocol)}, \textbf{VRRP (Virtual Router Redundancy Protocol)}, and \textbf{GLBP (Gateway Load Balancing Protocol)}. These protocols ensure high availability and fault tolerance by providing redundancy for default gateway routers in a network.

\subsection*{Topology Components}
The topology consists of the following key components:

\begin{itemize}
\item \textbf{R1 (Router 1):} Serves as the upstream router that connects the network to external destinations.
\item \textbf{MLS (Multi-Layer Switches) 1, 2, 3, and 4:} Act as Layer 3 distribution switches that participate in FHRP to provide redundancy and load balancing for end devices.
\item \textbf{SW1 (Layer 2 Switch):} Functions as the access layer switch, connecting end devices (PC1 to PC6) to the network.
\item \textbf{End Devices (PC1 - PC6):} Represent client machines that rely on a stable and resilient default gateway for communication beyond their local subnet.
\end{itemize}

\subsection*{Interconnections and Purpose}
\begin{itemize}
\item The \textbf{end devices are connected to SW1} through FastEthernet ports (F0/1 to F0/6).
\item SW1 is connected to the \textbf{multi-layer switches (MLS1 - MLS4)} via uplink ports (F0/7 to F0/10).
\item Each \textbf{multi-layer switch is connected to the router (R1)} via FastEthernet links to provide redundancy at the Layer 3 distribution level.
\end{itemize}

\section{Introduction to HSRP Configuration}

\subsection{Overview of HSRP and Its Importance}
Hot Standby Router Protocol (HSRP) is a Cisco proprietary redundancy protocol that provides 
\textbf{high availability} for IP networks by ensuring a backup router takes over automatically 
when the primary router fails.

In the \textbf{topology provided}, we have:
\begin{itemize}
\item R1 (Router)
\item Four Multi-Layer Switches (MLS1, MLS2, MLS3, MLS4)
\item One Layer 2 Switch (SW1)
\item Six PCs (PC1 - PC6)
\end{itemize}

HSRP ensures \textbf{network uptime} by providing a \textbf{virtual gateway IP address}, 
which devices use as their default gateway. The \textbf{primary device} (Active Router) 
forwards packets, while the \textbf{secondary device} (Standby Router) takes over in case 
of failure.

\subsection{Configuring Preemption for Faster Failover}
\begin{itemize}
\item If the Active Router (\textbf{MLS1}) fails, \textbf{MLS2} takes over.
\item When MLS1 comes \textbf{back online}, it should \textbf{automatically reclaim the Active role}. 
This is done using \textbf{preemption}.
\end{itemize}

\section{Introduction to VRRP}

\subsection{Overview of VRRP and Its Importance}
The \textbf{Virtual Router Redundancy Protocol (VRRP)} is an open-standard redundancy protocol 
that provides high availability for \textbf{default gateways} by electing a \textbf{Master} and 
\textbf{Backup} router.

VRRP ensures that if the \textbf{Master Router fails}, a \textbf{Backup Router} takes over 
\textbf{seamlessly}, preventing network downtime.

In the \textbf{topology provided}, we have:
\begin{itemize}
\item Router (R1)
\item Four Multi-Layer Switches (MLS1, MLS2, MLS3, MLS4)
\item One Layer 2 Switch (SW1)
\item Six PCs (PC1 - PC6)
\end{itemize}

VRRP provides \textbf{fault tolerance} by allowing multiple \textbf{Layer 3 switches} to participate 
in the election process while hosts continue using a single \textbf{virtual IP address} as the 
default gateway.



\vspace{1.5em}

\subsection{Basic VRRP Concepts and Terminology}
\begin{itemize}
\item \textbf{Master Router}: The \textbf{active} VRRP router that handles traffic.
\item \textbf{Backup Router}: The \textbf{standby} VRRP router that takes over if the Master fails.
\item \textbf{Virtual Router}: The \textbf{group of devices} sharing a single \textbf{virtual IP}.
\item \textbf{Virtual IP Address (VIP)}: The \textbf{gateway address} used by end devices.
\item \textbf{VRRP Group}: Identifies multiple routers participating in the \textbf{same failover group}.
\end{itemize}

\section{Introduction to GLBP}

\subsection{Overview of GLBP and Its Benefits}
Gateway Load Balancing Protocol (\textbf{GLBP}) is a \textbf{Cisco-proprietary} redundancy 
protocol that provides both \textbf{gateway failover} and \textbf{load balancing} for network 
traffic. Unlike \textbf{HSRP} and \textbf{VRRP}, which only elect one active router at a time, 
GLBP enables multiple routers to \textbf{simultaneously} handle network traffic while offering 
redundancy.

\textbf{Key Benefits of GLBP:}
\begin{itemize}
\item \textbf{Load Balancing:} Distributes network traffic across multiple routers.
\item \textbf{Redundancy:} Ensures \textbf{automatic failover} if one router fails.
\item \textbf{Active Virtual Gateway (AVG):} Manages \textbf{multiple Active Virtual Forwarders (AVFs)} 
for traffic distribution.
\end{itemize}

\subsubsection{Network Topology Overview}
In our topology, we have:
\begin{itemize}
\item Router R1
\item Four Multi-Layer Switches (MLS1, MLS2, MLS3, MLS4)
\item One Layer 2 Switch (SW1)
\item Six PCs (PC1 - PC6)
\end{itemize}

Using \textbf{GLBP}, we will configure \textbf{MLS1 and MLS2} as \textbf{gateway routers}, ensuring that:
\begin{enumerate}
\item \textbf{Traffic is load-balanced} across multiple routers.
\item \textbf{Failover occurs automatically} if one router fails.
\end{enumerate}


\vspace{1em}

\subsection{Differences Between GLBP, HSRP, and VRRP}
\begin{center}
\begin{tabular}{|l|l|l|l|}
\hline
\textbf{Feature} & \textbf{GLBP} & \textbf{HSRP} & \textbf{VRRP} \\
\hline
\textbf{Load Balancing} & \checkmark \; Yes & \texttimes \; No & \texttimes \; No \\
\hline
\textbf{Master/Active Role} & Multiple Active Virtual Forwarders & Single Active Router & Single Master Router \\
\hline
\textbf{Preemption} & \checkmark \; Enabled by Default & \checkmark \; Configurable & \checkmark \; Enabled by Default \\
\hline
\textbf{IPv6 Support} & \checkmark \; Yes (GLBPv6) & \checkmark \; Yes (HSRPv2) & \checkmark \; Yes (VRRPv3) \\
\hline
\textbf{Object Tracking} & \checkmark \; Yes & \checkmark \; Yes & \checkmark \; Yes \\
\hline
\end{tabular}
\end{center}


\vspace{1em}

\subsection{Basic GLBP Concepts and Terminology}
\begin{itemize}
\item \textbf{Active Virtual Gateway (AVG)}: The router that assigns virtual MAC addresses 
to participating routers.
\item \textbf{Active Virtual Forwarder (AVF)}: Routers that \textbf{actively forward traffic} 
based on assigned MAC addresses.
\item \textbf{GLBP Group}: A set of routers configured together for redundancy.
\item \textbf{Virtual IP Address}: The single IP address shared across multiple routers in 
the GLBP group.
\end{itemize}

\section{GLBP Priority and Active Virtual Gateway (AVG) Election}

\subsection{Understanding GLBP Priority and AVG Role}
GLBP determines the \textbf{Active Virtual Gateway (AVG)} based on \textbf{priority values}. 
The AVG is responsible for assigning \textbf{Virtual MAC addresses} to the 
Active Virtual Forwarders (AVFs).

\begin{itemize}
\item The router with the \textbf{highest priority} becomes the \textbf{AVG}.
\item If the AVG fails, the router with the \textbf{next highest priority} takes over.
\item Default GLBP priority is \textbf{100}, but it can be \textbf{manually adjusted}.
\end{itemize}

\subsection{Debugging GLBP Load Balancing and Failover Issues}
When \textbf{GLBP does not work correctly}, consider the following common issues:

\subsubsection{Issue \#1: GLBP Not Load Balancing Traffic}
\textbf{Problem:} Traffic is only using one router.\\
\textbf{Solution:} Ensure \textbf{GLBP load balancing is enabled}:
\begin{lstlisting}
MLS1(config)# interface vlan 10
MLS1(config-if)# glbp 1 load-balancing weighted
\end{lstlisting}

\subsubsection{Issue \#2: GLBP Preemption Not Working}
\textbf{Problem:} The higher-priority router is not reclaiming AVG.\\
\textbf{Solution:}
\begin{itemize}
\item Verify that \textbf{preemption is enabled}:
\begin{lstlisting}
MLS1(config-if)# glbp 1 preempt
\end{lstlisting}

\item Check if \textbf{tracking is reducing the priority} below the backup router’s priority:
\begin{lstlisting}
MLS1# show glbp vlan 10
\end{lstlisting}

\item Manually increase the priority:
\begin{lstlisting}
MLS1(config-if)# glbp 1 priority 120
\end{lstlisting}
\end{itemize}

\subsubsection{Issue \#3: Hosts Cannot Reach the Virtual Gateway}
\textbf{Problem:} PCs cannot ping \texttt{192.168.10.1 (GLBP Virtual IP)}.\\
\textbf{Solution:}
\begin{itemize}
\item Check if VLAN \textbf{interface is up} on both switches:
\begin{lstlisting}
MLS1# show ip interface brief | include Vlan10
\end{lstlisting}
\item If it shows \textbf{"administratively down"}, enable it:
\begin{lstlisting}
MLS1(config)# interface vlan 10
MLS1(config-if)# no shutdown
\end{lstlisting}
\end{itemize}
